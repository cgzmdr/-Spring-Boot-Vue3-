## 1. 文档说明

### 1.1 目的

本文档旨在定义「走进多彩 56 个民族世界」主题网站前端产品的需求边界、功能范围、交互规范、视觉与技术架构，作为设计、开发、测试与验收的统一依据。

### 1.2 范围

- 覆盖范围：面向 C 端用户的 Web 前端（响应式，覆盖 PC / 平板 / 移动端）。
- 不在范围：后端管理后台（CMS）、内容审核系统、运营报表系统的详细设计（本文档仅定义其前端依赖的接口与数据契约）。

### 1.3 术语定义

| 术语 | 说明 |
| --- | --- |
| 民族（Ethnic Group） | 中华民族 56 个民族中任意一个民族实体 |
| 条目（Entry） | 单个内容实体，如「节日」「风俗」「艺术」「美食」 |
| 专题（Topic） | 围绕某一主题聚合的内容集合，如「民族团结」「非遗传承」 |
| 响应式（Responsive） | 一套代码自适应多端屏幕尺寸 |
| 断点（Breakpoint） | 响应式布局切换的屏幕宽度阈值 |

## 2. 项目背景与目标

### 2.1 背景

中华民族由 56 个独特民族构成，承载着丰富多彩的文化传统与民族风情。它不仅是多元文化魅力的展示平台，也是促进民族团结与和谐的重要力量。

传统民族文化传播长期面临以下痛点：

1. **信息碎片化**：内容分散于百科、新闻、短视频，缺乏系统、权威、结构化的呈现。
2. **呈现形式单一**：以文字与静态图片为主，缺乏沉浸式与交互式的数字体验。
3. **可触达性弱**：地域与语言藩篱阻碍全球观众了解中华文化。
4. **年轻群体触达不足**：传统叙事方式难以吸引 Z 世代用户主动探索与分享。

### 2.2 项目目标

「走进多彩 56 个民族世界」网站运用尖端 Web 前端响应式技术，打破地域藩篱，将各民族的风俗习惯、节日庆典与传统文化以数字化形式呈现给全球观众。

**核心目标：**

1. **系统性呈现**：为 56 个民族建立统一、完整、权威的数字化文化档案。
2. **沉浸式体验**：通过多媒体（图文、音视频、动效、3D/地图）打造可探索的文化空间。
3. **民族团结传播**：以「多元一体」为叙事主线，讲好中华民族共同体的故事。
4. **全球化触达**：多语言、无障碍、高性能，服务全球观众。

### 2.3 成功指标（KPI）

| 指标 | 目标（上线后 3 个月） |
| --- | --- |
| 首页首屏 LCP | < 2.5s（4G 网络） |
| 全站跳出率 | < 45% |
| 人均浏览页数 | ≥ 4 页 / 次 |
| 民族详情页平均停留时长 | ≥ 90s |
| 移动端占比 | ≥ 55% |
| Lighthouse 性能评分 | ≥ 90 |
| 核心内容可访问性（WCAG AA） | 100% |

## 3. 目标用户与使用场景

### 3.1 用户画像

| 画像 | 特征 | 核心诉求 | 关键场景 |
| --- | --- | --- | --- |
| 文化爱好者 | 25–45 岁，对民族文化、人文历史感兴趣 | 系统了解某一民族的文化全貌 | 浏览民族详情、阅读深度文章 |
| 学生 / 研究者 | 16–28 岁，因课业或课题需要查证资料 | 快速检索、获取权威信息 | 搜索、筛选、收藏引用 |
| 旅行者 | 22–50 岁，计划前往民族地区旅游 | 了解当地节日与风俗禁忌 | 查看节日时间、风俗须知 |
| 海外华人 / 外国观众 | 对中华文化好奇，多语言背景 | 低门槛理解，跨语言阅读 | 切换语言、浏览精选专题 |
| 教育工作者 | 教师 / 家长，用于科普教学 | 生动素材、可分享的内容 | 查找节日庆典、传统艺术 |

### 3.2 用户故事（User Stories）

- 作为文化爱好者，我想**在首页就能看到各民族的精选亮点**，以便快速决定从哪里开始探索。
- 作为学生，我想**按民族、节日、艺术等多维度搜索与筛选**，以便高效获取所需资料。
- 作为旅行者，我想**查看某个民族的重要节日时间与风俗禁忌**，以便规划行程并避免冒犯。
- 作为海外观众，我想**切换到我熟悉的语言**，以便无障碍理解内容。
- 作为移动端用户，我想**在手机上流畅浏览和分享**，以便随时随地传播。

## 4. 产品定位与核心价值

### 4.1 定位

**一站式、沉浸式、可探索的中华民族数字文化博物馆。**

### 4.2 核心价值主张

1. **全（Complete）**：56 个民族全覆盖，每个民族 6 大内容维度（概况、风俗、节日、艺术、美食、聚居地）。
2. **活（Alive）**：以多媒体与动效让文化「活」起来，而非静态陈列。
3. **易（Accessible）**：多语言、无障碍、高性能，人人可及。
4. **亲（Inclusive）**：以「多元一体」贯穿叙事，彰显民族团结。

## 6. 功能需求详述

### 6.1 全局功能

#### 6.1.1 顶部导航栏（P0）

| 项 | 说明 |
| --- | --- |
| Logo | 点击返回首页 |
| 主导航 | 首页 / 民族 / 节日 / 艺术 / 关于 |
| 搜索入口 | 图标或输入框，点击展开搜索 |
| 语言切换 | 中 / 英（预留多语言扩展） |
| 移动端 | 汉堡菜单收纳导航，展开为抽屉 |

**交互要求：**
- 页面滚动超过阈值后导航栏吸顶（sticky），背景半透明毛玻璃（frosted glass）。
- 当前所在频道高亮。

#### 6.1.2 语言切换（P1）

- 默认中文，支持英文；语言包采用 `i18n` 方案，文案与路由解耦。
- 语言选择持久化（`localStorage`），刷新后保持。

#### 6.1.3 搜索（P0）

- 支持关键词模糊搜索，覆盖：民族名、节日名、艺术类别、美食、关键词标签。
- 搜索结果分组展示（民族 / 节日 / 艺术 / 其他）。
- 支持拼音搜索（如输入 `zangzu` 匹配「藏族」）。
- 热门搜索词、历史搜索记录。

#### 6.1.4 主题色 / 暗色模式（P2）

- 遵循系统偏好（`prefers-color-scheme`），可手动切换。

### 6.2 首页（Home）

| 模块 | 优先级 | 需求说明 |
| --- | --- | --- |
| Hero 视觉区 | P0 | 全屏沉浸式首屏，展示主题标语与动态民族纹样背景，含 CTA（开始探索 / 了解 56 民族） |
| 56 民族入口 | P0 | 以色块云图 / 网格呈现 56 个民族，支持悬浮预览，点击进入详情 |
| 精选专题 | P0 | 横向滑动卡片（如「民族团结」「非遗传承」「节日盛宴」） |
| 节日聚合 | P1 | 近期节日时间线 / 卡片，标注民族与日期 |
| 艺术聚合 | P1 | 传统艺术精选（音乐 / 舞蹈 / 手工艺） |
| 数据可视化 | P2 | 民族分布地图、人口概览等轻量可视化 |

**Hero 设计要点：**
- 背景采用可交互的粒子/纹样动效，但需控制性能开销（首屏 `< 200KB` 动效资源，避免阻塞 LCP）。
- CTA 按钮符合无障碍对比度要求。

### 6.3 民族频道

#### 6.3.1 民族列表页（P0）

- **展示形式**：卡片墙（Grid），卡片含民族名、代表图、简介（一句话）、所属语系/地域标签。
- **筛选维度**：
  - 地域（东北 / 西北 / 西南 / 中南 / 东南 / 内蒙古 / 其他）
  - 语系（汉藏语系 / 阿尔泰语系 / 南岛语系 / 南亚语系 / 印欧语系 / 混合）
  - 人口规模（区间）
  - 首字母 / 拼音排序
- **交互**：筛选条件组合后实时更新结果；支持「重置」；结果数量提示。
- **性能**：列表分页或虚拟滚动，首屏仅加载可视区卡片（懒加载图片）。

#### 6.3.2 民族详情页（P0，核心页面）

**页面结构：**

1. **顶部横幅（Hero）**：民族代表图 / 视频背景，民族名 + 民族语自称 + 人口 / 分布核心指标。
2. **概览区**：基本信息卡（人口、主要聚居地、语言、文字、宗教、历史沿革）。
3. **Tab 内容区**（6 大维度）：
   - 风俗习惯：婚嫁、丧葬、饮食、服饰、礼仪、禁忌。
   - 节日庆典：节日列表，含时间、起源、习俗。
   - 传统艺术：音乐、舞蹈、戏剧、手工艺、建筑。
   - 特色美食：代表性饮食图文。
   - 聚居地：地图定位 + 地域介绍。
   - 图集 / 影像：多媒体画廊。
4. **关联内容**：相关民族、相关节日、相关艺术条目。

**交互要求：**
- Tab 切换支持锚点 / 路由，可被分享（如 `/ethnic/tibetan#festivals`）。
- 图片点击放大（Lightbox），支持左右切换。
- 内容支持「收藏」「分享」「点赞」。
- 面包屑导航：首页 > 民族 > 藏族。

## 7. 交互与页面规范

### 7.1 通用交互原则

- 遵循「飞书 / Notion」式现代 B 端产品体验：块级层次清晰、动效克制、反馈及时。
- 所有可点击元素具备 `hover` / `focus` / `active` 状态。
- 关键操作需有明确反馈（加载态、空态、错误态）。

### 7.2 状态设计

| 状态 | 要求 |
| --- | --- |
| 加载中 | 骨架屏（Skeleton），避免白屏 |
| 空态 | 图文提示 + 引导动作（如「重置筛选」） |
| 错误态 | 友好提示 + 重试按钮 |
| 无网络 | 离线缓存提示（PWA） |

### 7.3 动效规范

- 时长 150–300ms，使用 `transform` / `opacity` 优先，避免 `layout` 触发重排。
- 尊重 `prefers-reduced-motion`，提供关闭动效选项。

## 8. 视觉设计规范

### 8.1 设计理念

- **关键词**：多彩、包容、传统与现代融合。
- 从民族服饰与纹样中提取色彩体系，但保持整体克制、不喧宾夺主。

### 8.2 色彩

| 用途 | 色值（建议） | 说明 |
| --- | --- | --- |
| 主色 | `#C0392B`（中国红，可微调） | 品牌主色，用于 CTA、高亮 |
| 辅助色 | 各民族主题色（按民族分配） | 用于民族标识 |
| 中性色 | `#1F2937` 文字 / `#F5F5F4` 背景 | 保证可读性 |
| 语义色 | 成功 / 警告 / 错误 | 状态反馈 |

### 8.3 字体与排版

- 中文：系统字体栈（`PingFang SC` / `Microsoft YaHei` / `Noto Sans SC`）。
- 英文：`Inter` / 系统默认。
- 标题层级清晰，正文行高 1.6–1.8，正文最小字号 16px（移动端不小于 14px）。

### 8.4 图标

- 采用 **SVG 图标**（`iconfont` / `lucide` / 自定义 SVG），保证清晰度与可缩放性。
- 民族纹样等装饰性图形使用 SVG，避免位图失真。

## 9. 响应式设计规范

### 9.1 断点策略

| 断点 | 范围 | 布局 |
| --- | --- | --- |
| 移动端 | < 640px | 单列，卡片纵向堆叠，汉堡菜单 |
| 平板 | 640–1024px | 双列 / 三列，底部 Tab 或抽屉导航 |
| 桌面 | ≥ 1024px | 多列网格，完整顶部导航 |

### 9.2 移动端优先（Mobile First）

- 先设计移动端布局，再向上扩展。
- 触摸目标 ≥ 44×44px。
- 图片按断点加载不同尺寸（`srcset` / 响应式图片）。

## 10. 非功能需求（NFR）

### 10.1 性能

- 首屏 LCP < 2.5s，FCP < 1.8s，CLS < 0.1。
- 图片统一使用 WebP / AVIF，惰性加载，压缩至合理尺寸。
- 代码分割（Route-level code splitting），首屏 JS 体积控制。
- 静态资源 CDN 分发，配置缓存策略。

### 10.2 可访问性（Accessibility）

- 遵循 WCAG 2.1 AA：语义化标签、`alt` 文本、`aria` 属性、键盘可达。
- 对比度满足 4.5:1（正文）/ 3:1（大字）。

### 10.3 SEO

- SSR / SSG（预渲染）保证核心内容可被搜索引擎抓取。
- 每页独立 `title`、`description`、`Open Graph` 标签。
- 语义化 HTML（`article`、`nav`、`main`、`header`）。

### 10.4 国际化（i18n）

- 支持中 / 英双语，文案与数字格式（日期、农历）本地化。
- `lang` 属性切换，`hreflang` 支持多语言 SEO。

### 10.5 跨平台 / 兼容性

- 支持主流现代浏览器（Chrome / Edge / Safari / Firefox 近 2 个大版本）。
- 预留 PWA 能力（离线缓存、可安装），为桌面端（Electron/Tauri）同构预留空间。

### 10.6 安全

- 前端渲染内容需防 XSS（内容来源于 CMS，需净化）。
- 第三方资源使用 `rel="noopener noreferrer"`。
- CSP 策略配置。

## 11. 技术架构方案

### 11.1 技术选型

| 层 | 技术 | 说明 |
| --- | --- | --- |
| 框架 | Vue 3（`<script setup>`） | 现有项目基础，组合式 API |
| 语言 | TypeScript | 类型安全 |
| 构建 | Vite | 快速构建与 HMR |
| 路由 | Vue Router | 路由级代码分割 |
| 状态管理 | Pinia | 轻量状态（筛选、语言、主题） |
| UI 组件 | 自研设计系统 + 按需引入（Naive UI / Element Plus） | 保证风格统一 |
| 样式 | UnoCSS / Tailwind + CSS 变量 | 主题化与响应式 |
| 数据请求 | Axios / Fetch + TanStack Query | 请求缓存与状态 |
| 内容渲染 | SSR / SSG（Nuxt 或 Vite SSR） | SEO 与首屏 |
| 动画 | CSS Transition + 轻量动画库 | 性能优先 |
| 国际化 | vue-i18n | 多语言 |

> 注：当前项目为纯前端 Vue 3 + Vite + TS 脚手架，尚未引入路由 / 状态管理 / UI 库。本 PRD 为后续迭代的完整目标架构，具体落地可分期实现。

### 11.2 目录结构（建议）

```
src/
```

## 16. 验收标准

1. 56 个民族均可通过列表进入详情，且 6 大维度内容完整可读。
2. 全站响应式适配 PC / 平板 / 移动端，无横向滚动与内容截断。
3. 搜索可命中民族名、拼音、节日、艺术类别。
4. 语言切换后全站文案同步更新，无硬编码中文。
5. 关键页面 Lighthouse 性能 ≥ 90，可访问性达 WCAG AA。
6. 核心页面可通过分享链接直达并正确渲染（SEO 可抓取）。

## 17. 风险与后续规划

### 17.1 风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 56 民族内容量大，资料收集周期长 | 上线延期 | 优先保证 P0 内容，分批次补齐 |
| 图片 / 视频资源体积大 | 性能下降 | CDN + 压缩 + 懒加载 + 响应式图片 |
| 多语言翻译成本高 | 国际化滞后 | 首期中英双语，预留多语言扩展 |
| 农历日期换算复杂 | 节日展示不准 | 引入成熟农历库，后端下发规范日期 |

### 17.2 后续规划

- 用户账号体系与收藏云端同步。
- 3D / 地图沉浸式探索（民族分布可视化）。
- 桌面端（Electron / Tauri）同构应用。
- 更多语言（少数民族语言、法、西、阿语等）。
- 社区 UGC（用户上传民族见闻，审核后展示）。
